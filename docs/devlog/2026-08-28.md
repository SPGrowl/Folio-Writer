# 开发日志 · 2026-08-28

## 16:00 · 移除旧版 chat-store

### 背景
经典聊天主路径已迁至 `sessionStore` + Bubble，旧 `chat-store` 仍被 Layout / Header / usingContext / 导入导出误用，造成双轨状态与假开关。

### 改动前
- **设计**：并行两套会话模型（扁平 `Chat[]` + `History` vs `Session` + `ChatTurn`）；`usingContext` 仅存在于旧 store，且不进入真实请求。
- **实现**：`useChatStore`、`useChat`、`useUsingContext`、旧 `Message` 组件；Header 标题读旧 `history`；设置页导入导出读写 `chatStorage`。
- **架构**：Pinia `chat-store` 与 `session-store` 并存，路由同步仍依赖旧 `active`。

### 改动后
- **设计**：聊天会话唯一数据源为 `sessionStore`；去掉上下文模式 UI/文案。
- **实现**：删除 `store/modules/chat`、`useChat`、`useUsingContext`、`Message` 组件栈；Layout/List/Header 改挂 session；设置页改用 `sessionStorage`（清空时顺带移除遗留 `chatStorage`）；`sessionStore` 补 `goHome`。
- **架构**：store 导出去掉 chat；`chat.d.ts` 仅保留 Session/Turn/Bubble 类型。

### 其他方案（讨论未采用）
- **用 Agent step 统一替换经典聊天** → 未采用原因：产品职责不同（纯对话 vs 工具工作台），本轮目标仅为清冗余。
- **保留 usingContext 并接到 composeRequest** → 未采用原因：开关早已与请求脱节，属假功能，直接移除更干净。

### 涉及范围
- 关键路径/模块：`store/modules/chat`（删）、`session`、`Layout`/`List`/`Header`、`chat/index.vue`、`Setting/General.vue`、`typings/chat.d.ts`、locales、旧 `Message`/`hooks`
- 兼容性 / 迁移：旧 `chatStorage` 数据不再被读取；设置「清空」会同时删 `chatStorage`；导入导出改为 `sessionStorage` 格式

## 16:05 · 收敛为单语中文并约定 Agent 不用 i18n

### 背景
多语言包使改文案与 Agent 适配成本过高；产品以简体中文为主，无需继续维护 7 语。

### 改动前
- **设计**：vue-i18n 多 locale + 设置页语言切换；Agent 核心仍有少量 `t()`。
- **实现**：en/es/ko/ru/vi/zh-TW 与 zh-CN 并存；`Language` 联合类型与 naive-ui 语言包切换。
- **架构**：UI / store / agent 均可依赖 `@/locales`。

### 改动后
- **设计**：仅保留 `zh-CN`；设置页去掉语言入口；历史 `language` 本地设置强制收敛为 `zh-CN`。
- **实现**：删除其它 locale 文件；`useLanguage` 固定 naive-ui `zhCN`；`src/agent` 与 `store/modules/agent` 去掉 i18n，文案硬编码中文。
- **架构**：新增 `.cursor/rules/agent-no-i18n.mdc`，约定 Agent 核心开发不再使用 i18n（Compose UI 的 `$t` 暂保留）。

### 其他方案（讨论未采用）
- **彻底拆除 vue-i18n，全站硬编码中文** → 未采用原因：改动面过大；本轮先单语 + Agent 禁 i18n，性价比更高。
- **保留 i18n 结构但继续维护多语文件** → 未采用原因：适配成本正是要消除的问题。

### 涉及范围
- 关键路径/模块：`locales/`、`useLanguage`、`app` helper/store、`Setting/General.vue`、`agent/tool/*`、`store/modules/agent`、`.cursor/rules/agent-no-i18n.mdc`
- 兼容性 / 迁移：旧语言偏好被忽略并写回 `zh-CN`；Compose 侧栏 UI 仍可用 `$t`（仅 zh-CN 文案）

## 21:02 · 移除设置 Config 页与聊天记录导入导出

### 背景
设置中的 Config（About/服务配置展示）与聊天记录导入导出属于上游模板能力，当前产品不需要。

### 改动前
- **设计**：设置含 General / Advanced / Config 三页；General 可导出、导入、清空本地会话存储。
- **实现**：`About.vue` 拉取 `/config`；`General.vue` 读写 `sessionStorage`/`chatStorage`。
- **架构**：前端 `fetchChatConfig` 对接后端 `/config`。

### 改动后
- **设计**：设置仅保留 General + Advanced（精简模式下仅 General）；无配置页、无会话导入导出。
- **实现**：删除 `About.vue` 与 Config 页签；去掉 General 中聊天记录区块；移除前端 `fetchChatConfig`。
- **架构**：后端 `/config` 路由暂留（无前端调用）。

### 其他方案（讨论未采用）
- **连同 Advanced（采样参数）一并移除** → 未采用原因：本次明确是「配置界面」与导入导出；Advanced 仍是调参入口。
- **同步删除后端 `/config`** → 未采用原因：非本次必需，避免扩大服务端改动。

### 涉及范围
- 关键路径/模块：`Setting/index.vue`、`General.vue`、`About.vue`（删）、`api/index.ts`
- 兼容性 / 迁移：无；本地会话仍由 `sessionStore` 正常读写，只是不能从设置页导入导出

## 23:02 · 移除精简模式、提示词商店与空清除按钮

### 背景
精简模式只是把一批上游遗留能力藏起来；清除上下文按钮实现为空；提示词商店与 Advanced 调参页实际很少用。

### 改动前
- **设计**：`liteMode` 控制 Advanced / PromptStore / Config 显隐；移动端 Header 有清空按钮（无逻辑）；聊天输入支持 `/` 提示词补全。
- **实现**：`PromptStore` + `prompt-store` + `recommend.json`；`Advanced.vue`；`setLiteMode`；空 `handleClear`。
- **架构**：设置多页签；侧栏底部挂提示词商店入口。

### 改动后
- **设计**：去掉精简模式与提示词体系；设置仅保留通用（用户信息/主题）；Header 仅保留导出。
- **实现**：删除 PromptStore/Advanced/prompt 模块；聊天输入改为普通 `NInput`；`appSetting` 读取时丢弃历史 `liteMode`。
- **架构**：`settingStore` 仍保留默认 systemMessage/temperature/modelName 供请求使用，只是不再提供 Advanced UI。

### 其他方案（讨论未采用）
- **去掉 liteMode 但保留 Advanced/PromptStore 常显** → 未采用原因：这些能力本身也是遗留，一并瘦身更干净。
- **连同 settingStore 默认参数一并删除** → 未采用原因：聊天与 Agent 请求仍依赖这些字段。

### 涉及范围
- 关键路径/模块：`Setting/*`、`General`、`Header`、`chat/index`、`List`、`app` store、`prompt`（删）、`PromptStore`（删）、`zh-CN` locales
- 兼容性 / 迁移：本地 `promptStore` / `liteMode` 数据不再使用；采样参数回落到 settings 默认值（若用户曾在 Advanced 改过，本地 `settingsStorage` 仍生效）
