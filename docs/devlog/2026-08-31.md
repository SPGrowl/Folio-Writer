# 开发日志 · 2026-08-31

## 15:02 · 后端 pgvector 向量库启动与文章索引

### 背景
为后续 `search_article` 做准备：先具备向量扩展、切片表，以及文章增改时的切块/embedding 入库；检索 HTTP 接口暂不实现。

### 改动前
- **设计**：文章仅存 PostgreSQL 正文，无语义索引。
- **实现**：Prisma `articles` CRUD，无 pgvector。
- **架构**：service 启动只测 pg/Prisma 与默认分组。

### 改动后
- **设计**：`article_chunks` 存切片 + `vector(N)`；文章 create/update 后异步重建索引；删除靠 FK CASCADE。
- **实现**：`ensureVectorStore` 幂等建扩展/表/HNSW；`chunkMarkdown` + OpenAI-compatible `embeddings.create`；`scheduleReindexArticle` 挂到 articles CRUD。
- **架构**：新增 `service/src/db/vector/*`；SQL `migrate_article_chunks.sql`；环境变量 `EMBEDDING_*`。

### 其他方案（讨论未采用）
- **Prisma 原生管理 vector 列** → 未采用原因：维度与 raw SQL 检索仍不可避免，先用 pool + DDL 更直观。
- **同步阻塞写入等 embedding 完成** → 未采用原因：避免拖慢文章保存；失败只打日志，主流程不失败。
- **同步实现检索 API** → 未采用原因：按需求本轮只做库启动与索引写入。

### 涉及范围
- 关键路径/模块：`service/src/db/vector/*`、`articles.ts`、`index.ts`、`sql/migrate_article_chunks.sql`、`.env.example`
- 兼容性 / 迁移：需 PostgreSQL 安装 pgvector；未配 embedding 时可启动但跳过索引；维度变更须重建 `article_chunks`
