# 开发日志

## 2026-08-20

### Agent 工具展示：三槽预填，按 status 取值

工具 step 的 `msg` 从单行字符串改为与 `status` 同键的 `{ running, done, error }`。派生卡片时用 `buildToolMsg` 按函数名填好三句中文模板；侧栏读 `step.msg[step.status]`。

执行成功后先 `patchToolMsgSlot` 覆盖 `done`（补字数 / 待审句），再把 `status` 改为 `done`，避免 `Object.assign` 整键替换冲掉另外两句。失败只切 `status`，error 句出卡时已带标题。

各工具文件的 `formatRunning/Done/Error` 已删，registry 只留 `execute`。`patch_article_content` 展示文案与 `update_article_content` 共用。文案暂硬编码中文。

### 修复 thinking 模式 400：`reasoning_content` 必须回传

`runTurn` 会先 push 一条 `streaming` 占位 assistant 再 `buildRequest`。原先 `session.steps` 整链编进 messages，首轮实际发出 `[system, user, assistant{content:''}]`。thinking 开启时上游把这条空 assistant 当成历史回复，因缺少 `reasoning_content` 返回 400。

`buildRequest` 现在跳过 `status === 'streaming'` 的 assistant（与主对话 `composeRequest` 当前轮只发 user 对齐）。已完成的 assistant 仍由 `stepToApiMessage` 在字段有值时带上 `reasoning_content`。

### Agent 侧栏：上拉查看历史时不跟滚到底

原先 `watch(activeSteps, { deep: true })` 每次流式/工具更新都 `scrollTo` 底部。改为仅在距底部 ≤80px 时跟滚（`stickToBottom`）；用户发送、新建/切换会话、关闭当前会话仍强制滚到底。跟滚使用直接改 `scrollTop`，避免每个 token 一次 `smooth` 抖动。
